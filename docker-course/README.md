# Приложение для курса Docker

Готовое приложение показывает сообщение и версию, а при подключении PostgreSQL сохраняет заметки. Оно находится отдельно от основного DevOps-приложения. Для прохождения курса достаточно Docker, Compose, Git и терминала. На Windows команды курса выполняются в терминале WSL с Linux-контейнерами Docker Desktop.

## Готовый образ

Из этого каталога поставляемый скрипт собирает учебный образ. Он самостоятельно читает Dockerfile и устанавливает зависимости. Для первого запуска требуется сеть, чтобы получить базовый образ и пакеты.

```sh
sh prepare-image.sh
docker run --rm -p 127.0.0.1:8080:3000 docker-course:1.0.0
```

В браузере приложение доступно по адресу <http://localhost:8080/ui>. Команда `curl http://localhost:8080/` возвращает сообщение и версию `1.0.0`. Версия читается из файла _VERSION_ внутри образа, значение `SERVER_MESSAGE` меняет только сообщение.

## Входное состояние урока

Скрипт копирует приложение в новый каталог и добавляет подготовленные файлы из `states/<slug>`, когда они есть. Он отказывается менять непустой каталог. Для состояния `configuration` и последующих состояний скрипт создаёт файл _secrets/db-password.txt_ с учебным паролем `course-password`. Файл доступен для чтения непривилегированным процессом, а `.gitignore` и `.dockerignore` исключают его из Git и образа. Этот демонстрационный пароль используется только в локальном учебном окружении.

```sh
sh prepare.sh docker-compose ../docker-compose-work
cd ../docker-compose-work
```

Поддерживаются слаги `intro`, `run`, `application`, `container-management`, `images`, `network`, `bind-mounts`, `image-creation`, `image-layers`, `docker-compose`, `configuration`, `readiness`, `development`, `best-practices`, `releases` и `diagnostics`.

## Контракт приложения

Приложение слушает `0.0.0.0:3000`. Настройка `PORT` позволяет заменить порт. При отсутствии `PGHOST` приложение работает без базы. При наличии `PGHOST` оно подключается к PostgreSQL и ожидает заранее созданную таблицу заметок. Сама HTTP-служба может работать до готовности базы, а проверка готовности в это время возвращает 503.

| Запрос | Результат |
| --- | --- |
| `GET /` | JSON с полями `message` и `version` |
| `GET /ui` | Интерфейс с сообщением, версией и заметками |
| `GET /ready` | 200 без базы или при доступной таблице `notes`, иначе 503 |
| `GET /notes` | JSON-массив заметок с `id` и `text`, без БД возвращает 503 |
| `POST /notes` с JSON `{"text":"Запись"}` | Сохраняет заметку и возвращает её с кодом 201 |

Обычный параметр `SERVER_MESSAGE` заменяет текст из _message.txt_. Приложение читает файл при запуске, поэтому синхронизация файла в работающем контейнере требует перезапуска процесса.

Подключение использует `PGHOST`, `PGPORT` (по умолчанию 5432), `PGUSER` (по умолчанию `course`), `PGDATABASE` (по умолчанию `course`) и `PGPASSWORD`. Вместо `PGPASSWORD` можно передать `PGPASSWORD_FILE`, например `/run/secrets/db_password`. Одновременная передача обоих источников отклоняется. Приложение не печатает пароль в лог.

## Готовые команды

Все команды выполняются внутри каталога приложения в контейнере. Параметры подключения берутся из окружения процесса. Инициализация безопасно повторяется на существующей схеме.

```sh
node scripts/init.mjs
node scripts/notes.mjs write 'Первая заметка'
node scripts/notes.mjs read
node scripts/healthcheck.mjs
```

Проверка готовности возвращает код 0 при HTTP 200 и код 1 при отказе. `SIGTERM` останавливает HTTP-сервер и закрывает соединения с базой. Для отдельного опыта с лимитом памяти служит `node scripts/memory.mjs`. Процесс записывает данные в буферы объёмом до 256 МиБ и удерживает их, поэтому его запускают только в выделенном контейнере с лимитом памяти.

Управляемый сбой приложения позволяет проверить политику перезапуска. Команда посылает `SIGUSR2` основному процессу, который пишет событие `controlled_failure` и завершается с кодом 1. Скрипт проверяет Linux, наличие Docker-контейнера и запуск `server.mjs` процессом с PID 1. При запуске на хосте он отказывается отправлять сигнал.

```sh
docker compose exec app node scripts/crash.mjs
```

## Сборка

_Dockerfile_ показывает простую сборку. Команда `pnpm run build` копирует шаблон интерфейса из _ui/index.html_ в готовый файл _public/index.html_. _Dockerfile.production_ содержит стадии `dependencies`, `build`, `dev` и `runtime`. Итоговая стадия `runtime` запускает приложение от `node` на slim-образе. Она получает готовый интерфейс, а скрипт сборки остаётся в стадии `build`. Стадия `dev` оставляет инструменты, необходимые Watch, и разрешает пользователю `node` менять файлы в `/app`.

```sh
docker build -t docker-course:1.0.0 .
docker build -f Dockerfile.production --target runtime -t docker-course:1.0.0 .
docker build -f Dockerfile.production --target dev -t docker-course:dev .
```

Файл _.dockerignore_ исключает `.env`, `secrets`, Git, зависимости хоста и входные состояния из контекста сборки. Секреты не входят в образ.

## Проверка без контейнера

Для разработки самого приложения нужны Node.js 24 или новее и pnpm указанной в _package.json_ версии.

```sh
pnpm install --frozen-lockfile
pnpm test
```

Проверки HTTP покрывают версию, сообщение, ошибки запроса и режим без базы. Интеграция с PostgreSQL проверяется отдельно в сценариях курса.
